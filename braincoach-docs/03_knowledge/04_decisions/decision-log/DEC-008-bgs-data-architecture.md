# DEC-008 — BGS Data Architecture

## Status

Approved

## Date

2026-06-10

---

# Context

Первая версия BrainCoach строилась одновременно с разработкой инфраструктуры.

В результате появились базы и сервисы, названия которых отражают историю создания системы:

* braincoach_dev
* n8n_v2_clean
* n8n-db-instance

Такой подход приемлем на этапе прототипирования, но плохо масштабируется в Knowledge OS.

Названия начинают описывать инструменты и этапы разработки вместо функций системы.

Для долгосрочного развития необходим переход к функциональной архитектуре данных.

---

# Decision

В качестве целевой архитектуры Brain Growth System (BGS) принимается разделение данных по ролям и функциям.

Базы данных должны описывать ответственность слоя системы, а не конкретный инструмент.

Целевая структура:

## bgs_core

Источник истины системы.

Содержит:

* Knowledge OS
* Ontology
* Memory
* Events
* Canon
* Registries
* Decisions

Назначение:

Единая долговременная память экосистемы.

---

## bgs_orch

Оркестрационный слой.

Содержит:

* workflow state
* agent state
* queues
* orchestration metadata
* n8n runtime data

Назначение:

Управление агентами и процессами.

---

## bgs_vector

Слой семантического поиска.

Содержит:

* embeddings
* vector indexes
* retrieval metadata
* RAG infrastructure

Назначение:

Поиск знаний и контекстная память.

---

## bgs_analytics

Слой исследований и аналитики.

Содержит:

* маркетинговые исследования
* контент-аналитику
* продуктовые эксперименты
* behavioral analytics
* метрики

Назначение:

Понимание происходящего и поддержка принятия решений.

---

## bgs_observability

Слой наблюдаемости.

Содержит:

* logs
* traces
* audit records
* monitoring metrics
* health checks

Назначение:

Контроль состояния экосистемы.

---

# Architectural Principle

Система должна быть организована вокруг функций.

Нельзя проектировать архитектуру вокруг текущих инструментов.

Допустимо менять:

* n8n
* Vertex AI
* LangGraph
* PostgreSQL extensions
* vector databases
* orchestration engines

Недопустимо нарушать функциональное разделение:

* Core
* Orchestration
* Vector
* Analytics
* Observability

---

# Human-AI Governance Model

Целевая модель управления:

Человек не является маршрутизатором знаний.

Человек принимает ограниченное число стратегических решений.

Экосистема выполняет большую часть операционной работы.

Ориентир:

* 4% стратегических решений принимает человек
* 96% рутинных действий выполняют агенты

---

# Consequences

Будущие сервисы должны проектироваться относительно BGS-слоев.

При создании новых агентов, workflow, сервисов и баз данных сначала определяется слой системы, а затем технология реализации.

Архитектура BrainCoach рассматривается как единая экосистема знаний, исследований, автоматизации и принятия решений.

Данное решение становится базовым ориентиром для дальнейшего развития BrainCoach Knowledge OS.
