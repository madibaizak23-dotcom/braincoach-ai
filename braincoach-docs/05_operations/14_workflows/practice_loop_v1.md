## Practice Decision

BrainCoach foundation is now used as daily practice, not only as documentation.

The same thinking loop must be used for:

* founder self-tracking;
* client tracking;
* marketing analysis;
* offer discovery;
* product decisions;
* agent reasoning.

The tracker is the intake channel.

The Practice Loop is the interpretation and correction channel.

The tracker should also act as external working memory.

It helps the founder use previously studied sources without relying on biological memory to hold all details at once.

Weekly Sprint is the planning channel.

It turns intentions, habits, events, content work, study blocks, client work, and preparation into a visible weekly control loop.

## Time Luck Principle

Practice Loop treats time sense as a trainable capability.

Founder formulation:

```text
Время везёт меня, когда я использую время и действую по плану.
```

In this practice, luck is not only an external event.

Luck is the experienced effect of being in the right action at the right time.

The tracker should therefore help train:

* remembering the plan when the moment arrives;
* feeling what action the current time is asking for;
* acting inside the intended timing window;
* noticing when stress narrows attention and erases the plan;
* correcting the next sprint from timing deviations.

Operational criterion:

```text
Can the user remember the plan and feel the right time for action even under stress?
```

This applies to breathing practice, stories, reels, production blocks, founder learning, client work, and recovery windows.

## Council Mode

BrainCoach tracker should support the founder as if a methodological council were available nearby.

This does not mean pretending to be the authors or producing decorative quotations.

It means applying the preserved methods from:

* Goldratt / TOC;
* Altshuller / TRIZ;
* Lobanov / Russian Logic;
* DOTU collective authors;
* Sociology foundation sources;
* adaptation patterns / radicals.

The council mode must translate a raw tracker entry into several disciplined questions:

```text
DOTU asks:
What is being controlled, toward what goal, with what feedback?

Goldratt / TOC asks:
What is the current constraint and what assumption keeps the conflict in place?

Altshuller / TRIZ asks:
What contradiction is present and what stronger resolution is possible without weak compromise?

Lobanov / Russian Logic asks:
Are the terms, quantifiers, premises, and conclusion valid, or is the state still indeterminate?

DOTU / Sociology asks:
What layer of behavior, culture, psyche, environment, or social process is active?

Adaptation / radicals ask:
What perception or action pattern may be influencing the person, and how can support be adjusted without labeling?
```

Council Mode output should be practical.

Minimum output:

1. preserved raw thought;
2. system / object;
3. likely constraint;
4. contradiction;
5. logical status;
6. adaptation hypothesis if useful;
7. one next action or experiment;
8. feedback signal to watch.

If the entry is not ready for action, the agent should mark it as:

```text
indeterminate
needs more observation
```

and ask one precise question that would reduce uncertainty.

## Core Loop

Every meaningful tracker entry should move through this loop:

```text
Raw tracker idea / observation
->
DOTU control frame
->
Current reality and goal vector
->
TOC constraint
->
TRIZ contradiction
->
Logic discipline
->
Adaptation / radical lens
->
Decision or experiment
->
Action
->
Feedback from reality
->
Updated model
```

The purpose is to create a self-correcting loop.

BrainCoach should help the founder and clients become more capable of:

* seeing reality earlier;
* detecting constraints;
* formulating contradictions;
* avoiding false binary conclusions;
* choosing stronger actions;
* measuring feedback;
* correcting the model without ego defense.

## Personal Tracking Use

When the founder sends an idea into the tracker, the agent should not only save it.

The agent should classify the idea as one or more of:

* observation;
* hypothesis;
* contradiction;
* constraint;
* offer signal;
* marketing signal;
* product signal;
* personal development signal;
* decision candidate;
* unresolved / indeterminate.

Then the agent should run the minimum practice check:

1. What object or system is this about?
2. What goal vector is implied?
3. What current reality is visible?
4. What deviation or dissatisfaction is visible?
5. What constraint may be operating?
6. What contradiction is present?
7. What is the logical status: validated, contradicted, or indeterminate?
8. What adaptation pattern or radical may be influencing perception or action?
9. What action or experiment follows?
10. What feedback will show whether the action improved control?

## Client Tracking Use

For clients, the same loop is used with stricter language discipline.

Client-facing language must not expose heavy theory directly.

Internal frame:

```text
DOTU / TOC / TRIZ / Logic / Adaptation Pattern
```

Client-facing translation:

```text
What is happening?
What are we trying to improve?
What is blocking movement?
What tradeoff keeps repeating?
What small action can test the next step?
What signal will show progress?
```

The goal is not to label the client.

The goal is to improve trajectory visibility and self-correction.

## Marketing Use

Marketing should use the Practice Loop to avoid producing content from intellectual interest alone.

Each content idea must answer:

1. What market pain does this express?
2. What real tracker signal or client observation supports it?
3. What diagnostic phenomenon explains it?
4. What mechanism is likely operating?
5. What contradiction or constraint keeps the pain alive?
6. What next step has value?
7. What conversion signal will validate the message?

Marketing formula:

```text
Market Pain
->
Tracker / Client Signal
->
Diagnostic Phenomenon
->
Mechanism
->
Next Step
->
Conversion Feedback
```

## Adaptation / Radical Lens

Radicals and adaptation patterns are used as diagnostic lenses, not labels.

They may help detect:

* preferred control style;
* avoidance pattern;
* perception bias;
* conflict response;
* motivation channel;
* stress behavior;
* compensating strategy.

Required rule:

```text
Pattern is a hypothesis.
Behavior is the observation.
Feedback decides whether the hypothesis is useful.
```

Agents must not present radicals as identity labels.

Agents must not reduce a person to a pattern.

Agents may use the lens only when it improves:

* question quality;
* support strategy;
* action design;
* feedback interpretation.

## Ternary Logic In Practice

Every tracker-derived conclusion must keep three states available:

```text
validated
contradicted
indeterminate
```

Indeterminate is not a failure.

It is a correct state when evidence is incomplete, ambiguous, or still forming.

Agent rule:

```text
Do not turn candidate insight into truth.
Do not turn unknown into false.
Do not turn repeated wording into evidence.
```

## TOC In Practice

Every weekly review should name the current constraint.

Examples:

* payment trigger not yet proven;
* unclear offer transition;
* low quality of tracker entries;
* weak feedback loop;
* too much production before demand proof;
* client not seeing value after interview;
* founder attention split across non-constraints.

The agent must ask:

```text
If we improve only one thing this week, what changes the system most?
```

## TRIZ In Practice

When a repeated tradeoff appears, the agent should not accept compromise too quickly.

Required TRIZ questions:

1. What do we want to improve?
2. What worsens when we improve it?
3. What contradiction is this?
4. What resource is already present in the system?
5. Can separation by time, space, level, role, function, or condition resolve it?
6. What experiment tests the stronger option?

## DOTU In Practice

Every serious review must define:

1. Object of control
2. Goal vector
3. Current state vector
4. Deviation vector
5. Environment
6. Control function
7. Feedback
8. Correction
9. Control mode

If these are missing, the review is not complete.


```text

```

```text

```

```text

```

```text

```

The agent should preserve raw wording and add structured interpretation separately.

## Weekly Review Protocol

Weekly review should produce:

1. strongest observed facts;
2. repeated patterns;
3. current constraint;
4. major contradiction;
5. validated signals;
6. contradicted assumptions;
7. indeterminate candidates;
8. one or two decisions;
9. experiments for the next week;
10. feedback measures.

The review must separate:

```text
fact
pattern
inference
hypothesis
decision
feedback
```

## Operating Rule For Agents

Agents should help the founder and clients grow by tightening the loop:

```text
Observe
->
Interpret
->
Choose
->
Act
->
Measure
->
Correct
```

An answer is incomplete if it only explains.

An answer is complete when it improves the next decision, action, or feedback loop.
