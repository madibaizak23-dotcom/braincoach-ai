# BrainCoach Automation — Object States v1.0

Status: Active

Date: 2026-06-05

---

# Purpose

This document defines lifecycle states for canonical BrainCoach objects.

Objects do not remain static.

Objects evolve through states.

Automation should operate on state transitions rather than isolated records.

---

# Core Principle

Objects move.

Knowledge evolves.

Reality changes.

The purpose of states is to represent that evolution.

---

# State Categories

Objects may exist in one of four lifecycle stages:

## Emerging

Recently detected.

Requires observation.

---

## Active

Currently relevant.

Requires processing.

---

## Validated

Confirmed through evidence.

May be reused.

---

## Archived

No longer active.

Preserved for historical reference.

---

# State Transition Rule

Objects may only move forward through valid transitions.

State changes must be recorded.

State history must be preserved.

---

# Research Rule

The system should prioritize movement from:

Observation

↓

Signal

↓

Phenomenon

↓

Research

↓

Model

↓

Knowledge

The purpose of automation is to accelerate these transitions.
